# Birthday app security boundaries

The collection and original photos/recordings are private. Every user API call needs a valid `av_session` cookie: an HMAC-SHA256 signature over its issue time, keyed by a random session key in D1, valid for one year and re-signed after 30 days of use. A phone gets the cookie only by redeeming a single-use, 60-minute pairing token, shown as a QR on the frame or copied from Settings on an already signed-in phone. Tokens travel in the URL fragment, so they never reach logs. "Sign out all phones" rotates the session key. Anyone who can see the frame while a code is showing can pair; that is accepted because the frame is in the recipient's home. /device/* relies on its independent Worker bearer credential. The device credential cannot authorise /api/* or read originals.

Local development permits a separate bearer only with ENVIRONMENT=local and a loopback request hostname. Vite's loopback proxy adds it server-side through DEV_API_TOKEN. Never deploy local credentials or ENVIRONMENT=local. .dev.vars, .env files, .wrangler state and model caches are excluded from version control and Docker build context. Production requires distinct device, inference and renderer secrets; no secrets belong in public Vite variables or static assets.

Original media is in private R2, exposed only through authorised Worker endpoints. Inference and rendering receive only required bytes/settings, through internal Durable Object bindings with separate service tokens. Production does not accept arbitrary service URLs; local service URLs must use loopback. Containers have internet disabled and max_instances=1 per service. Model downloads happen at image build time. Upload limits, recording duration and bounded job retries reduce accidental resource consumption; they do not replace billing alerts or usage review.

Deleting the final sighting removes its capture and original; shared audio survives while another sighting references it. Backups retain deleted media until their retention window expires and therefore need the same privacy protection as live storage. Keep encrypted copies separately, as described in RECOVERY.md. This project has not yet proved hosted pairing on a real iPhone, cloud restoration or physical device setup; deployment gates are recorded in DEPLOYMENT.md.

Serve everything from one hostname and disable workers.dev/preview URLs. The UI shell and bird artwork are public static files and hold nothing personal. Never expose the container services or the R2 bucket publicly. See DEPLOYMENT.md for the pairing and device path contract and the hosted verification gate.
